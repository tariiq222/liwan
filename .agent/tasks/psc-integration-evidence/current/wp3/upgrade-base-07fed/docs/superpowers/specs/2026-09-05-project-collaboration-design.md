# Project collaboration design

Status: approved intent from user; implementation in isolated codex/project-collaboration.
Baseline: b17058a. User requested plan and Luna team execution of attachments, notifications, task dependencies and archived-task restoration. Root owns coordination and verification; Sol supplied architecture decisions and reviews; Luna implements.

## Architecture and constraints
Reuse stock Odoo 19 CE project.task, ir.attachment, mail.message and mail.notification. Extend nasq_pmo, preserve Odoo upstream and HR. Nuxt remains customer UI. No commits, merges, pushes, deployment, canonical-runtime changes or cleanup are authorized. Read CLAUDE.md and docs/parallel-work.md. Session cookie JSON2 API, explicit methods, api_handler and whitelisted responses; errors 403 forbidden,404 not_found,422 invalid with field where appropriate. Arabic default RTL and English translations. Existing shared API contracts remain compatible.

## Attachments
Task detail gains upload/delete management. POST /api/v1/tasks/{id}/attachments accepts {name,mimetype,data} with base64 data, maximum decoded size 10 MiB. GET same route returns {items,total}; DELETE /api/v1/tasks/{id}/attachments/{attachment_id} returns 204. Attachment item {id,name,mimetype,url}; downloads use existing /web/content/{id}?download=true. Allow PDF, PNG, JPEG, plain text, DOCX, XLSX; reject executable/HTML/SVG and invalid base64, blank/path filenames, empty files, oversize input. Bound encoded length before decoding; server detects MIME from bytes where practical rather than trusting filename. Reads require task read; writes require task write, exact res_model=project.task/res_id link; refuse message-only/URL attachments or cross-task identifiers. No public attachment or sudo bypass. Return structured validation errors. UI shows pending/error, confirms delete inline within the attachment row, supports file-picker reset/reupload, refreshes task detail after changes.

## Task dependency editing
Use stock depend_on_ids, allow_task_dependencies and cycle detection. Only project managers as defined by _nasq_can_manage may enable the project feature or edit dependencies. ProjectDetail/Patch gains allow_task_dependencies boolean. GET /api/v1/tasks/{id}/dependencies returns {items,total,can_manage,enabled}; items {id,name,state}. PUT same path accepts {ids:number[]} and returns full TaskDetail. GET /api/v1/tasks/{id}/dependencies/candidates?q=&limit=&offset= returns {items:[{id,name,state}],total}; picker searches and pages all readable active same-project candidates including open and closed tasks, excluding self. Detail dependency serialization re-searches linked ids in the caller environment to omit unreadable prerequisites. Require same project, valid unique positive ids, no self/cycles and task write access. Disabled setting rejects adding links, allows clearing existing links. Preserve Odoo blocked/waiting behavior. Task detail adds can_manage_dependencies flag default false in schema for older fixtures, explicitly serialized by server. UI represents links with remove/add controls, pending writes and server errors.

## Archived tasks
GET /api/v1/tasks/archived?project_id=&q=&limit=&offset= returns {items,total}, items use existing Task shape. Require scope project_id or filter=mine. Include only archived readable tasks with active parent projects that caller may restore (project manager or creator); count respects the same policy and UI supports loading subsequent pages. POST /api/v1/tasks/{id}/unarchive returns full TaskDetail; explicit active_test=False lookup, read/write check and manager-or-creator guard; reject restoration while project archived with 422 archived_project. Existing archive policy unchanged. Add customer route /archived-tasks with project_id and filter=mine queries and restore buttons; link it from tasks and project page secondary actions. Do not add active fields to ordinary Task wire shape. Revalidate normal lists, project counters and milestones after restore.

## In-app notifications
Use stock mail.message and mail.notification, no replacement notification table. GET /api/v1/notifications?limit=&offset=&unread= returns {items,total,unread_count}; items {id,kind,task_id,task_name,body,created_at,is_read}, kind assignment|comment|deadline. POST /api/v1/notifications/{id}/read and POST /api/v1/notifications/read-all return {updated:number}. Poll inside app every 30 seconds while authenticated; bell links to the dedicated /notifications page and shows unread count; the page supports load-more, read-all, and clicking an item marks it read then opens the task. Full workflows use internal routes, never drawers, following the standing Nasq UI rule. Keep UI under notifications namespace.

Explicitly scope every query/mutation to current partner, nasq notification marker and CURRENT readable active task/project. Access revocation removes rows, content and counts; another recipient's id returns 404. Exclude actors from their own assignment/comment alerts. Assignment alerts only newly added internal assignees; comment alerts to other internal assignees. No outgoing email or web push; create inbox records intentionally instead of invoking broad mail delivery. A dedicated inherited project.task model owns hooks, leaving original project_task.py to task worker. Use stock mail.message markers/extra fields as needed for kind/dedup identity, document narrowly justified sudo paths for delivery and recipient-owned notification read without permitting unrelated access. Do not use message_post recursively for marker messages.

Hourly cron checks active open tasks due today/tomorrow in explicit company/user timezone policy; one deadline notification per recipient and exact deadline. Implement persisted deterministic key plus database uniqueness and transactional conflict handling; changing deadline or assignee may produce new notice, reruns do not. Closed/archived/unreadable tasks excluded. Store UTC dates, serialize existing iso helper format. Tests invoke cron manually, final runtime cron disabled. Default in-app only selected after optional channel question without answer.
