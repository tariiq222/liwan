# خطة تحسين تجربة المشاريع

> الحالة: **اعتمدها المستخدم وبدأ تنفيذها في نسخة معزولة** في 16 أكتوبر 2026. لا كومت أو دمج أو نشر. سجل القبول النهائي يوثق ما تحقق وحدوده.

**Goal:** رحلة مشاريع واضحة من الوصول والإنشاء إلى المتابعة والقرار والحفظ والرجوع، مع تقليل تشتت التخطيط وإضافة سجل معلم مفيد.

**Architecture:** تحسين صفحات ومكونات PMO الحالية باستخدام قوالب نسق؛ جمع الجدول الزمني والمعالم تحت التخطيط بروابطهما الحالية؛ سجل معلم جديد؛ نقل تحرير الجدولة إلى سجل مهمة المشروع دون نسخ وظائف أو تغيير عقد الخادم.

**Tech Stack:** Nuxt 4، Vue، Nuxt UI، TanStack Query، عقود Zod الحالية، Vitest، Playwright، Storybook. مصدر البيانات Odoo الحالي؛ لا تغييرات addon أو schema مفترضة.

**Spec:** [التصور ونتائج المراجعة](../specs/2026-10-16-projects-ux-design.md)، وعقود القبول A1–A9 فيه.

**سجل التنفيذ والقبول:** [النتائج الفعلية وحدود الدليل](../../verification/2026-10-16-projects-ux.md). المراحل الخمس مكتملة محليًا؛ خانات الإجراءات أدناه محفوظة بصفتها قائمة الخطة الأصلية، والأدلة في التقرير هي مرجع حالة التحقق.

## Global constraints

- مصدر المراجعة main عند `0733a7501d1552b3b0257c4a6b560ba878326ef1`. يعاد فحص main والعمل غير المحفوظ عند بدء التنفيذ؛ لا نسخ تغييرات قديمة فوق عمل أحدث.
- التنفيذ في worktree مؤقت مستقل عن نسخة الوثائق، بعد التحقق من وجود نسخة مناسبة. تبقى node_modules و.nuxt مستقلة؛ منافذ وقاعدة scratch خاصة، لا اختبارات على odoo19.
- الدفعات الأولى نُفذت بالتتابع لارتباط عقود السياق. بناء على طلب المستخدم إطلاق إيجنتات منظمًا، وُزعت الدفعة الأخيرة على ثلاث نسخ مستقلة بملكية ملفات منفصلة: حماية إعدادات المشروع، اتساق المتابعة والمالية، ومتانة الجدولة. المنسق يملك الملفات المشتركة والتشغيل ونقل التغييرات والتحقق، ثم مراجع مستقل. لا دمج Git ضمن ذلك.
- الحفاظ على صلاحيات الخادم، حالات الأرشفة، تعريفات التقدم والمعالم والميزانية. لا توسيع صلاحية أو إسقاط حقول أو اعتماد ضمن تعديل واجهة.
- الميثاق له مسودة وحفظ وإرسال واعتماد؛ لا دمج لهذه النتائج في نجاح واحد. المالية لها تعارض نسخة، ويظل التقدير الأولي منفصلًا عن ميزانية السجل.
- المهام الشخصية ومهامي خارج إعادة التصميم؛ المكونات المشتركة لا تتغير إلا بعقد واضح واختبار أثرها على مهامي. تظل ملكية الاجتماعات لتطبيقها.
- يُعدل الكود في موضعه. شاشة الجدولة القديمة تزال وظيفتها بعد نقلها؛ لا مساران نشطان للتحرير ولا مكونات old/new أو نسخ محلية من مكون معتمد.
- يعدل DESIGN.md فقط بعد اعتماد تغيير خريطة الصفحات؛ تحدّث قصص المكونات الموجودة. إذا احتجنا لبنة مشتركة جديدة يلزمها قصة وفهرس وفق السياسة.
- لا يبرر نجاح mock ادعاء نجاح الحفظ مع Odoo. كل مرحلة تنتج سجل قبول مختصر: الرحلة، الدور، البيانات، النتيجة، الدليل وما لم يختبر.
- لا كومت أو دمج أو push أو تنظيف للنسخ والفروع دون تفويض لاحق. تراجع قواعد الدمج والاختبارات الواسعة عند دخول التكامل في النطاق.

## تشغيل الاختبارات وقبول التنفيذ لاحقًا

اختبارات المتصفح القديمة تتضمن شروط skip ومنافذ/بيانات متخصصة وبعض توقعات تنقل قديمة؛ لا يعد وجودها أو خروجها الأخضر قبولًا. أثناء التنفيذ تربط suites الجديدة بالـmock/fixture المناسبين وتراجع تعداد الاختبارات المنفذة والفاشلة والمتجاوزة. لا تغير بيانات fixture لاختبار صلاحيات Odoo بدلًا من اختباره.

الأمر التالي **مثال تشغيل بعد إنشاء الملفات وتشغيل runtime مستقل صالح**، وbase URL يختار من تخصيص المنافذ الفعلي حينها:

```sh
E2E_BASE_URL=http://127.0.0.1:4404 npm -w apps/web run test:e2e -- project-ux-navigation.spec.ts project-ux-overview.spec.ts project-ux-create.spec.ts project-ux-planning.spec.ts project-ux-journeys.spec.ts
```

يفحص المشغل البيانات وتسجيل الدخول والأعلام المطلوبة؛ لا تثبيت اعتماد على 4404 إن كانت مشغولة. اختبارات Odoo الحقيقية تستخدم scratch وفق docs/agents/odoo-rules.md ولا تسند إلى runtime mock.

بعد اجتياز الاختبارات المركزة لكل دفعة، ينفذ المنسق مرة عند اكتمال الدفعة المترابطة:

```sh
npm -w apps/web run lint
npm test
git diff --check
```

ثم تحقق بصري/تفاعلي للرحلات على النسخة المعزولة وسجل نتائجها. عند اعتماد دمج مستقل لاحقًا، تضاف بوابات integration-rules وgit_policy وarch_policy على أحدث main؛ هذه الخطة لا تمنح تفويض الدمج.

## مخرجات كل مرحلة ونقطة التسليم

1. روابط الصفحات وقصص المكونات المعدلة وملخص التغيير.
2. نتائج الأوامر الفعلية وعدد اختبارات المتصفح المنفذة، مع أمثلة فشل/صلاحيات وحفظ.
3. ما جرى إثباته على mock، وما ثبت على Odoo scratch، وما بقي غير متحقق.
4. فتح النسخة للمستخدم ليجرب رحلة المرحلة قبل الانتقال لما بعدها، دون كومت أو دمج إلا بتفويض صريح.

## مراجعة ذاتية للخطة — إعداد فقط

- فصلت إضافة صفحة المعلم عن جمع عرضي التخطيط وعن إزالة شاشة الجدولة؛ لا تحذف وظيفة قبل تحقق التكافؤ.
- غطت كل حزمة صفحات موجودة، مع بقاء مراجعة الأدوار والحفظ الحقيقي ضمن التنفيذ.
