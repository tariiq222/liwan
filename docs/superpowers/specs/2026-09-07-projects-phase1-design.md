# Projects phase one design — 2026-09-07

> تاريخي. السياسة: [DESIGN.md](../../../DESIGN.md). ليس تعليمات واجهة.

## Approval and scope
The user approved the two-phase direction and requested isolated planning and implementation with delegation without further pauses. Phase one delivers project templates, stakeholders/RACI, risks/issues and Timeline/Gantt. Phase two (cost ledger, actual budget and consolidated reports) remains separate. The existing charter estimate is preserved.

## Architecture
Extend stock project/task/milestone through nasq_pmo; Arabic-first Nuxt internal pages; strict Zod contracts and same-origin session APIs. Existing timeline is activity history, so project scheduling is a separate resource. No new dependency, Enterprise/OCA module or timesheet surface.

## Stakeholders and RACI
Project-scoped stakeholders contain name, optional internal user, organization, role, contact and notes. External contacts do not grant login or project access. Task-scoped RACI rows reference a stakeholder in the same project and one of R/A/C/I. One A per task, at most one row per task/stakeholder (a role may be changed); zero A allowed while drafting. User picker remains res.users. CRUD internal list/detail/edit/create routes; RACI is an internal project matrix page with inline value selectors. Lists use items/total and expose can_manage. Reads require readable active current-company project; writes require project management and ORM guards. Linked stakeholder deletion is rejected with 409 until assignments removed.

## Risks and issues
One project register with kind risk/issue, title, description, priority low/normal/high/critical, status open/in_progress/resolved/closed, nullable internal owner, due date, response/action and nullable task. Risk adds probability and impact 1..5, with derived score; issue stores these as null. Filters are in URL. Creating/editing/details are internal routes; deletion has inline confirmation. Validate dates, enums, same-project task, current-company internal owner, immutable project and kind-consistent fields on API and ORM. No automatic conversion or workflow engine.

## Schedule
project.task gains nasq_planned_start (Date, copy=False). End remains stock date_deadline (UTC datetime). Schedule API uses date-only YYYY-MM-DD start/end (UTC date of deadline), refuses invalid/reversed dates, allows clearing both. Manager-only dedicated schedule write; ordinary task write routes must not gain this field inadvertently. Reads return only readable tasks/milestones; omit invisible dependency ids. Gantt page supports week/month scale, dated/undated tasks, status, milestone markers and visible predecessor links, and internal date-edit page. Empty/error/loading states, Arabic RTL, keyboard links, bounded visual axis for long spans. No drag/drop or automatic cascading scheduling. Private method task._nasq_set_schedule(start, end) accepts date objects or False and returns task; used by schedule API and template application.

## Templates
Company-scoped reusable definitions, not live project clones. Templates store stages (name/fold), milestones (key/name/offset_days), tasks (key/name/stage_key/start_offset/duration_days/milestone_key/dependency_keys). Template create/edit requires pmo.settings.manage; catalog read and use follows project read/create policy. Applying a template requires standard project creation policy, creates a new project owned by caller, stages, tasks and milestones atomically, calculates calendar-day offsets from chosen start, sets unfinished task state, creates no assignees/followers/activity/costs/issues. Task duration is a positive count of calendar days, with inclusive end = start + duration - 1; a one-day task ends on its start date. Template editable via internal pages, never JSON-only UI. Validate keys, finite bounded integer offsets/durations, references, cycles, duplicate keys and actual calendar dates in Zod and backend. Any invalid application rolls back everything. The template use page asks name/start and uses native creation policy/settings, including manager/end requirements. End derives from template span. Existing source projects are never mutated. Templates can be reused without sharing stage/task ids. Phase two may add template budget items.

## Integration contract and ownership
Schedule worker owns existing models/project_task.py and new schedule feature files. Templates calls _nasq_set_schedule. During integration, coordinator transferred narrowly scoped project_task.py ownership to the template correction worker to support native project creators without generic task create/read permissions. Governance owns new stakeholder/raci/register files. Each worker supplies feature-specific ACL CSV and record-rule XML and localization fragments under delivery/<feature>-ar.json and -en.json. Coordinator exclusively owns addon manifest and __init__ registration files, pmo barrel, project navigation and projects locale JSON. All feature contracts may import directly from their sibling modules; coordinator adds barrel exports. Source worktrees have the same d63f82f base, separate mutable dependencies. No commits, merges, pushes, runtime changes on canonical checkout or deletion. Coordinator copies reviewed owned files into integration worktree.

## Verified integration decisions
- Template application uses a server-owned cursor marker bound to caller, current company and freshly created project. Temporary task searches intersect only that project/company and retain stock ACL/rules; direct reads verify every ID. Population, result serialization and flush remain inside the same savepoint and finally clears the scope. Generic task read/create permissions remain unchanged outside application.
- Governance visibility uses live caller project/task SQL queries in a shared ORM _search/_check_access guard. Relational ir.rule domains alone are insufficient because Odoo19 optimizes those security domains with sudo. The original current-company/active global rules remain an additional floor.
- RACI viewport stores task/stakeholder searches, closed toggle and both pages in its URL; direct offset task queries restore cold links.
