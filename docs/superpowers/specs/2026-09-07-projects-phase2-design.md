## Product
Keep the charter estimate (unknown/estimate) intact. Add project finance entries of immutable kind budget or expense. A budget entry is a named planned amount (zero allowed); an expense is a named actual positive amount with required expense_date, optional reference/notes and optional link to a budget entry of the same project. No accounting, tax engine, approvals, attachments, timesheets, payroll, exchange rates or EVM. Company currency is read-only. Ordinary currency rounding uses the currency decimal places; reject inputs with excess precision, booleans, NaN, infinity, negative amounts and values above 1e12. Budget entry expense_date is null and budget_entry_id is null. Reject deleting a budget referenced by expenses with 409; delete expenses with inline confirmation. Editing and deleting require a revision token and return 409 on stale writes. Project identity/kind cannot change after creation. ORM safeguards cover direct RPC create/write/unlink as well as APIs.

## Summary meaning
All figures are lifetime figures, independent of ledger search/pagination. charter_estimate is null when unknown. planned is the sum of budget rows, null when no budget rows exist (explicit zero stays zero). actual is the sum of expenses (0 for none). remaining = planned - actual or null. over_budget = planned is not null and actual > planned. utilization_percent is null if planned is null or 0; otherwise actual/planned*100 rounded to two decimal places. budget_count and expense_count are whole-project counts.

## Routes and wire contracts
Frozen contracts live at packages/contracts/src/pmo/project-finance.ts and project-reports.ts.
GET /api/v1/projects/{id}/finance?kind=budget|expense&q=&limit=50&offset=0 returns {items,total,can_manage,summary}. limit 1..200, default 50; offset nonnegative. Unknown filters rejected. GET /finance/summary returns summary. POST /finance returns entry, 201. GET/PATCH/DELETE /finance/{entry_id}: full entry on writes; DELETE accepts {expected_updated_at} and returns {deleted:true}. PATCH requires expected_updated_at and at least one mutable field. Budget/expense form inputs must follow kind constraints against merged state. Nested ids must be scoped to route project.
Entry: {id,project_id,kind,title,amount,expense_date,reference,notes,budget_entry_id,updated_at}. updated_at is a monotonic vN revision, not a client timestamp. POST: kind,title,amount required; expense_date nullable optional, reference/notes default empty, budget_entry_id nullable optional. PATCH: title,amount,expense_date,reference,notes,budget_entry_id optional plus expected_updated_at required; kind/project_id forbidden. summary: {project_id,currency,charter_estimate,planned,actual,remaining,utilization_percent,over_budget,budget_count,expense_count}.
GET /api/v1/reports/projects?q=&status=unset|on_track|at_risk|off_track|on_hold|done&limit=50&offset=0 returns {items,total,totals}. Each row {project:{id,name,status},finance:summary,task_count,closed_task_count,overdue_task_count,progress}. Project status vocabulary must match existing ProjectStatusSchema (including null for unset); task counts/progress nullable when caller has no task-read capability; otherwise count only readable active tasks, done and cancelled are closed; overdue is deadline date < today UTC and unfinished. totals is an array by currency {currency,project_count,budgeted_project_count,planned,actual,remaining,over_budget_count}; monetary totals include all filtered visible projects, not current page. Totals planned sums only known budgets, actual sums all actuals, remaining sums remaining only for budgeted projects. No addition across currencies. Reports exclude archived/foreign/invisible projects and do not use the existing project-list 200 cap for total coverage.

## Security and architecture
Extend webvue_pmo only. Finance reads require pmo.projects.read plus live readable active current-company project. Writes require that plus project._webvue_check_manage. System admin has no implicit PMO write. Do not rely on relational record-rule joins alone to enforce parent visibility: Odoo19 may optimize these using sudo. Implement live caller project-query restriction for ORM search/access, global company/active rules as an extra floor, and operation guards. No new sudo case. Immutable company_id related stored readonly to project; never accept wire currency/company/creator/revision. Concurrency uses row lock and monotonically increasing revision inside transaction; recheck permissions after lock. All errors use shared api_handler and structured actual status 403/404/409/422. Whitelist serializers. Odoo stock checkout read-only; no tests on odoo19.

## Frontend

Forms use SharedUnsavedChanges and useHydrated for interaction; simple selectors permitted. Preserve filters with safe returnTo; direct links/refresh/back supported. /reports replaces placeholder with summary cards, search/status filtering, pagination and project links. Honest loading/empty/error states; unknown budget is visibly different from zero. Cache invalidates finance summaries/lists/details and reports after any mutation; edit cache replaced by server entry. Stale write preserves user's entered values and offers reload. No local-only fake controls. Add no dependencies. Coordinator adds finance link to project page and merges locale fragments; worker does not modify shared nav, project root page or locales.
