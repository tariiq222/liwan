# تحسين مساحة المشروع

طلب المستخدم «ابدأ» يعتمد تحسين القائمة، واستعادة آخر مكان، وتبسيط المهمة بعد رفض البدائل التجريبية. التنفيذ استمرار في فرع المعاينة `codex/project-layout`؛ لا دمج في main ولا تعديل للنموذج المؤقت.

## نطاق التنفيذ

- القائمة: `ContextSidebar.vue` يجمع المهام والمعالم قبل أقسام المتابعة والإعدادات. نفس المسارات والصلاحيات ومسار الصفحة.
- استعادة المكان: `projectWorkspaceMemory.ts` ينقح المسار والفلاتر؛ `useProjectWorkspaceMemory.ts` يحفظها في المتصفح تحت مفتاح الشركة والمستخدم والمشروع. التسجيل من القائمة الجانبية بعد تحميل المشروع بنجاح. الدخول عبر قائمة المشاريع أو المشاريع الأخيرة يستخدم التفضيل، مع استبدال سياق الرجوع بالقائمة الحالية. الروابط المباشرة تظل حرفية.
- يستثني الحفظ النماذج والإعدادات وتفاصيل السجلات. فشل التخزين أو فساده يعيد الدخول الافتراضي. لا مزامنة بين الأجهزة ولا تخزين بيانات المهمة أو المسودات. المقصود بالمكان القسم والفلاتر وطريقة العرض، وليس وعدًا باستعادة موضع التمرير.
- المهمة: تنفذ تعديلات العرض في `TaskDetailPanel.vue` و`TaskDetails.vue`؛ نطاق المشروع فقط مع بقاء السلوك الحالي خارج المشاريع، وبدون تغيير API أو الحفظ أو الاعتماد أو حماية المسودة.

## التحقق

اختبارات وحدة تنقيح الذاكرة: حفظ الفلاتر، استبعاد النماذج، منع المسار الخارجي أو المشروع الآخر، وتجديد سياق العودة. اختبارات متصفح: العودة إلى المخاطر بنفس البحث، استعادة لوحة المهام بعد تحديث المتصفح، احترام رابط الملخص المباشر، ترتيب القائمة، وإظهار التفاصيل الإضافية للمهمة. البيانات التجريبية على 3996/4396 وليست قاعدة Odoo فعلية. نتائج الفحص النهائية في تسليم المهمة.

النتائج: مجموعة الوحدة 758 اختبارًا ناجحًا؛ بعد إضافة تغطية فلاتر مصفوفة المسؤوليات نجحت المجموعة المركزة (ذاكرة المشروع ومكونات المهمة) بـ27 اختبارًا. نجحت 12 حالة متصفح للتغييرات والتنقل السابق. فحص TypeScript نجح. المراجعة المستقلة وجدت نقص مفاتيح بحث وصفحات مصفوفة المسؤوليات، وأضيفت المفاتيح واختبارها. لا تعد هذه الأرقام اختبار استخدام مع الفئات العمرية أو إثبات نشر.
