# Design documentation inventory

السلطة الوحيدة لواجهة العميل هي [DESIGN.md](../../../../DESIGN.md). هذا الجرد يصف
ما بقي من وثائق التصميم النشطة وما بقي كسجل تاريخي؛ لا يضيف تعليمات واجهة
ثانية ولا يعتمد على ملفات مصدر نموذجية.

## الوثائق النشطة

| المسار | الدور |
| --- | --- |
| `DESIGN.md` | دستور الشكل والسلوك المرئي وحفظ وظائف المنتج |
| `docs/design-system/components.md` | مالكو المكونات المركبة الفعلية في `apps/web/app` |
| `docs/design-system/README.md` | مدخل مختصر إلى دستور التصميم والفهرس |
| `docs/design-system/nuxt-ui-reference.md` | حدود Nuxt UI ومصدر التخصيص |
| `docs/archive/ui/design-system/migration.md` | حدود الترحيل والتنظيف وملكية محولات الرسوم |
| `docs/agents/frontend-theme.md` | دور تنفيذ/مراجعة الواجهة المرتبط بالدستور |

## السجل المحتفظ به

تقارير التحقق، الاعتماديات، القفل، الإعدادات، وفحوص الترحيل السابقة في هذا
المجلد محفوظة لأغراض التتبع. تواريخ الفروع والبيئات والنتائج الواردة فيها
تاريخية ومقيدة بسياقها؛ لا تتغلب على `DESIGN.md` ولا تثبت حالة التشغيل الحالية.
الوثائق المختلطة تحتفظ بعقود المنتج والأمن والبيانات اللازمة، وتزيل روابط
مصادر الشكل المتقاعدة.

## حدود الجرد

مكونات التشغيل، العقود، الاختبارات، أدوات السياسة، وثائق الاسترداد، وثيم
كونسول البائع تبقى في مالكيها. لا تُعد كلمة قديمة أو تاريخية في وثيقة منتج
دليلًا على أن وظيفة أو مسارًا أو سجلًا حُذف؛ يظل الحفاظ الوظيفي شرطًا لكل
تغيير بصري.
