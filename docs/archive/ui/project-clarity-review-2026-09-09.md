# مراجعة وضوح صفحات المشاريع — 2026-09-09

النطاق: واجهات المشاريع في متصفح الكمبيوتر، داخل فرع `codex/project-layout`. الهدف تقليل التكرار وجعل الأفعال والمعلومات مفهومة بسرعة. هذا فحص هندسي على بيانات تجريبية، وليس دراسة استخدام فعلية لأشخاص بأعمار 15 و60 سنة.

## المراجعة والتعديلات

| الأهمية | المجال والموقع | قبل | بعد وسبب التغيير |
| --- | --- | --- | --- |
| مرتفعة | ترتيب عناوين أقسام المشروع | اسم المشروع يظهر في الأب ثم عنوان الصفحة ثم عنوان الجدول | هوية المشروع في القائمة، وعنوان المحتوى اسم القسم؛ إزالة رؤوس الجداول المكررة في المخاطر والأطراف |
| متوسطة | قائمة المشاريع | تكرار كل المشاريع/مشاريعي والإحصائيات والإنشاء بين الصفحة والقائمة | التنقل في القائمة، وإنشاء المشروع مرة واحدة؛ بقاء البحث عند التنقل بين القائمتين |
| مرتفعة | البحث في المشاريع | البحث الأساسي خلف زر طي | البحث والفلاتر الأساسية ظاهرة عبر نمط FilterBar الموجود |
| متوسطة | كتابة المخاطر والأطراف | إنشاء وبحث ونتيجة دون سياق كافٍ | إضافة خطر أو مشكلة، بحث بالاسم أو الجهة، درجة الخطر؛ خيارات كل الأنواع والحالات والأولويات |

| مرتفعة | القراءة | نصوص صغيرة وباهتة في القائمة والجدول | تحسين أحجام النص والتباين ضمن المشاريع واحترام حجم الخط المختار في المظهر |
| مرتفعة | إعدادات المراحل | إعادة التسمية تتطلب اكتشاف النقر المزدوج | زر إعادة تسمية صريح، حقول معنونة، ودعم Enter وEscape |
| مرتفعة | قوالب المشاريع | أسماء مكررة وإزاحات غير واضحة وتحديد متعدد بمفاتيح خاصة | عناوين حقول ظاهرة، شرح الأيام من بداية المشروع، ومربعات اختيار للمهام السابقة |
| متوسطة | تفاصيل القالب | عدادات مستقلة تكرر أقسام القالب | دمج العدد بجانب اسم القسم |
| مرتفعة | إعدادات المشروع | حفظ تلقائي دون إشارة حالة | إظهار شرح الحفظ، جارٍ الحفظ، نجاحه أو فشله |
| متوسطة | نماذج المشروع والمالية | حقول بحث أو تاريخ دون اسم وصول واضح | تسميات وصول للمدير والمعتمد وتاريخ المصروف |
| متوسطة | ملف المشروع والجدولة والإعدادات | رأس تعديل ملف المشروع مفقود وأوصاف متكررة | عنوان تعديل واضح، وإبقاء كل وصف مفيد مرة واحدة |

بقيت المعلومات التي تؤدي وظيفة فعلية: شرح مصفوفة المسؤوليات، مقياس الخطر، الصلاحيات، حقول البحث عن السجلات واختيارها، حماية المسودات، والرجوع مع الفلاتر. لم تُحذف بيانات لتقليل كثافة الشاشة فقط.

## تغطية الصفحات

- كل المشاريع، مشاريعي، الإحصائيات، إنشاء المشروع.
- المهام والملخص والمعالم والجدولة، إنشاء/تفاصيل المهمة، تعديل الجدولة، إنشاء/تعديل المعلم.
- الأطراف والمسؤوليات والمخاطر والمشكلات والمالية: القائمة والإنشاء والتفاصيل والتعديل؛ مصفوفة المسؤوليات.
- ملف المشروع وعرضه وتعديله، إعدادات المشروع، التحديثات وإنشاؤها.
- إعدادات نظام المشاريع ونماذج التصنيفات المشتركة، وقوالب المشاريع: القائمة والإنشاء والتفاصيل والتعديل.

المراجعة شملت الترتيب، صياغة النصوص، أحجامها وتباينها، دلالات الحقول، استخدام لوحة المفاتيح وحالات التحميل والفراغ والفشل. اختبار النماذج يرصد العنوان والحقول والمظهر؛ لا يثبت حفظ كل نموذج على قاعدة Odoo حقيقية.

## أدلة التحقق وحدوده

اختبارات الواجهة في `apps/web/e2e/project-clarity.spec.ts` تغطي العناوين والقوائم والنماذج، التنقل مع البحث، إعادة التسمية بلوحة المفاتيح، اختيار المهام السابقة، وحالات عدم وجود نتائج وفشل الطلب. تنتظر لقطات المراجعة اكتمال التحميل. يوجد فحص عرض 1024 بكسل وتكبير CSS بنسبة 200% لأربع صفحات ممثلة؛ هذا ليس بديلًا عن اختبار تكبير المتصفح وقارئ الشاشة بالكامل.

نجحت مجموعة الوحدة: 754 اختبارًا، وفحص TypeScript عبر `npm -w apps/web run lint`. نجحت 48 حالة وضوح في المتصفح، ثم 30 حالة تحقق تشمل 25 حالة للتنقل وSide Sheet وخمس حالات معادة للوضوح، بينها حالة الاعتماد غير المكتمل. عند التكبير تضيق مساحة المحتوى ويحتاج الجدول إلى تمرير أفقي داخل حاويته؛ يمكن طي القائمة لزيادة المساحة. هذا لا يثبت اكتمال تجربة الشاشات الصغيرة.

البيانات من الخادم التجريبي المحلي على 3996/4396؛ لا دليل نشر إنتاجي أو اختبار قاعدة حقيقية. مراجعة الجوال مؤجلة حسب طلب المستخدم، ولم يجر اختبار مستخدمين من الفئات العمرية المذكورة أو اعتماد امتثال وصول شامل. التغييرات محلية ولم تُدمج أو تُنشر.
