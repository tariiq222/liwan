## النسخة المستهدفة لنسق

- يحافظ الغلاف على شريط الموديولات والقائمة السياقية والمسارات والصلاحيات.
- يبقى خط IBM Plex Sans Arabic المحلي، العربية/الإنجليزية، لون المؤسسة،
  المظاهر الثلاثة وأحجام الخط. `useAppearance` يملك الحالة وcookie، و
  `brandTheme.ts` يملك اشتقاق اللون؛ لا تنشئ حالة مظهر ثانية عند دمج Nuxt UI.
- المعاينة العربية قابلة للتجربة، وصورها مرشحة للمراجعة في
  [لقطات المرجع](reference/nuxt-ui/README.md). اعتماد الشكل لتعميمه يظل قرار المستخدم.
- لا تغيير Odoo أو API أو الملفات أو الطباعة أو حسابات المشاريع من أجل الثيم.

## وصفات الصفحات

نعيد استخدام مالكي نسق المشتركين بدل إنشاء مكتبة تغليف ثانية. أسماء Nuxt UI
أدناه خريطة ترحيل تطبيق العميل. مالكو المعاينة الفعليون ذوو بادئة `Preview`
موثقون في [الفهرس](components.md)، ومبنيون على المكونات المذكورة نفسها.

| الوصفة | التركيب والملكية |
| --- | --- |
| قائمة | `SharedPageContainer` و`SharedPageHeader` و`SharedFilterBar`؛ `UTable` وحقول Nuxt UI مع حفظ رقم السجل والفلاتر |
| تفاصيل | مالكو الصفحة أنفسهم وأقسام بيانات مشتركة و`UCard` عند الحاجة؛ الإجراء والرجوع واضحان |
| نموذج | `SharedFormSection` و`UFormField` وحقول Nuxt UI، مع أخطاء الخادم والتحقق وحماية المسودة؛ لا محرك نماذج جديد بلا حاجة |
| إعدادات | وصفة النموذج نفسها، مع تمييز نطاق الإعداد وحفظه والصفحات المستقلة |
| إحصائيات | `SharedDashboardChart` وUnovis مع أسطح وتوكنات الثيم؛ لا تغيير الحسابات أو مكتبة الرسوم تلقائيًا |
| سجلات جانبية | `ProjectRouteHost` يملك المسار والمسودة؛ تقييم `USlideover` للعرض دون فقد إغلاق/رجوع/صفحة كاملة أو تكديس |
| تخصص | المحادثات وGantt وRACI تستخدم نفس الحقول والأزرار والتوكنات؛ ليست ثيمًا ثانيًا |

## قبول مكوّن جديد

1. ابحث في Nuxt UI والفهرس؛ استخدم الموجود مباشرة إن كفى.
2. أضف إلى `components.md` مسار كل مكون جديد بين backticks، بصيغة
   `apps/web/app/components/.../Name.vue`، ومسؤوليته ووصفته ومكوناته الأساسية.
3. استخدم ألوان وأحجام ومسافات وحواف وخط وحالات الثيم، وCSS منطقي الاتجاه.
4. تحقق من التحميل/الخطأ/الفراغ/التعطيل، العربية/الإنجليزية، المظاهر والأحجام
   الثلاثة، لوحة المفاتيح وتقليل الحركة. بيّن سبب أي حالة غير منطبقة.
5. أرفق اختبارًا مناسبًا ولقطات فعلية؛ إضافة مسار إلى الفهرس ليست اعتمادًا
   بصريًا. لا ثيم محلي ولا مكتبة واجهات أخرى دون قرار المستخدم.

## الفحص المحلي

من جذر worktree، دون تثبيت حزم أو تشغيل قاعدة بيانات:

```sh
python3 -B tools/ui_policy.py
python3 -B -m unittest discover -s tools -p 'test_ui_policy.py' -v
```

يقارن الفحص مع خط البداية `fce4561330200947e4db88b508285fecf9bb05a5` وHEAD.
يسمح فقط بالاستعمالات القديمة الباقية في الملف نفسه، ويبلغ الإضافات؛ لا
تغير خط البداية لتجاوز فشل. يتطلب توفر هذا التاريخ في Git، وإلا يفشل.
يشمل مصادر الواجهة المتتبعة وغير المتتبعة غير المتجاهلة، وليس الاختبارات
أو ملفات التوليد. لا يكتب في ملفات المشروع.

يغطي الاستيرادات المعتادة للمكتبات، المكونات القديمة في Vue بصيغ PascalCase
وkebab-case، وبعض الاستعمالات الديناميكية النصية، وتسجيل المكونات الجديدة،
وألوانًا صريحة وتعريف ثيم محلي. يراجع أسماء اعتماديات الحزمتين الجذرية والويب؛
يسمح الفحص بـ`@nuxt/ui` و`@iconify-json/lucide` بالاسم، ويشمل مصدر المعاينة
بالقواعد نفسها. إضافة مكتبة واجهات أخرى تستلزم مراجعة وموافقة المستخدم،
لا توسيع قائمة السماح لإخفاء مخالفة.

وجود Reka كاعتمادية أساس لا يمنع Nuxt UI من استخدامها؛ الفحص يمنع التوسع
الجديد في استيراد مكوناتها الخام مباشرةً بدل Nuxt UI. حالة تخصص تستدعي ذلك
تحتاج مراجعة موثقة، لا استثناءً عامًا. يبقى استخدامها القائم أثناء الانتقال.

**الحدود:** تحليل نصي محدود، لا محلل Vue/TypeScript كامل ولا حد أمني؛ لا
يضمن كشف alias ديناميكي/استيراد محسوب أو كل قيم CSS أو صحة الألوان والأحجام
والوصول. البصريات والوظيفة تحتاج مراجعة واختبارات. المقارنة تعد الاستعمالات
لكل ملف؛ لا تكشف إزالة وإعادة نفس الاستعمال ضمن تعديل واحد. الفحص مربوط
ببداية `npm test` ويوقفه عند المخالفة؛ لا يوجد ربط بـCI أو hooks ولا منع
لتعديلات المستخدم على الفحص. هذا اختبار مصدر وليس هوك موافقة على الأدوات.

## ما يلي هذه الحزمة

اكتمل [توليد القفل ومراجعته](nuxt-ui-lock-result.md) ثم التثبيت وبناء المعاينة
وفق سياسة التشغيل المحلي الجديدة. تقارير الموافقة السابقة سجل تاريخي فقط.
القفل يحتوي تنبيهًا منخفضًا جديدًا خاصًا بخادم تطوير esbuild على Windows؛
ليس جاهزًا للدمج أو النشر، ولا تُفهم الموافقة المحلية على أنها قبول للنشر.

1. اعتماد الشكل في المعاينة الحقيقية؛ بياناتها لا تظهر في صفحات العملاء.
2. معالجة التنبيه الأمني الانتقالي قبل تبني القفل للنطاق العام.
3. ترحيل الغلاف والوصفات والمشاريع/المهام والاجتماعات وHR
   والإعدادات وبقية الصفحات، ثم المحادثات. لا استثناء للمحادثات من الثيم.
4. إزالة القديم بعد صفر مستهلكين واختبار البدائل. لا نسخ مشروع القالب فوق نسق.

التحقق عند الترحيل: Vitest والعقود، typecheck والبناء وPlaywright في بيئة
معزولة (لا اختبارات على `odoo19`)، مع المسار المباشر والتحديث والرجوع والفلاتر
والمسودات والصلاحيات وhydration والعربية. لا تضعف اختبارات السلوك لتنجح واجهة
جديدة؛ توقعات الشكل تتغير فقط وفق اعتماد المعاينة.
