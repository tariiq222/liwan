إلغاء الهوك التي أجراها المستخدم موجودة في main وworktree ومحفوظة كما هي؛
لا نعيدها ولا ننسبها إلى عمل الثيم. توجيهاتنا الجديدة حُدّثت لتتفق مع السياسة
الحالية، وتقارير الموافقة السابقة بقيت كسجل تاريخي.

## تشغيل قابل للإعادة

من جذر worktree، مع Node/npm المثبتين وملف القفل المحفوظ:

```sh
npm ci --ignore-scripts --strict-peer-deps --no-audit --no-fund
node node_modules/nuxt/bin/nuxt.mjs prepare apps/web
node node_modules/nuxt/bin/nuxt.mjs prepare apps/web/design-preview
node node_modules/nuxt/bin/nuxt.mjs dev apps/web/design-preview --host 127.0.0.1 --port 4317
```

لا تبدأ نسخة ثانية إذا كان 4317 مشغولًا. إعداد types للتطبيق الأب مطلوب لأن
المعاينة تعيد استخدام `brandTheme` و`normalizeAppearance` و`useHydrated`
من مصدره، ولا يشغّل API أو Odoo. ظهرت أثناء prepare تحذيرات أسماء واستيرادات
مكررة من ملفات التطبيق القديمة غير المعدلة؛ ليست أخطاء بناء المعاينة ولم
تُغيّر هذه الملفات لإسكاتها.

## خريطة التجربة

| المسار | ما يثبته |
| --- | --- |
| `/dashboard` | مؤشرات من بيانات المثال، رسم Unovis وخمسة سجلات حديثة |
| `/list?module=projects` | قائمة واحدة قابلة لإعادة الاستخدام مع فلاتر محفوظة في URL |
| `/list?module=tasks`، `meetings`، `hr` | نفس الوصفة والمكونات مع بيانات الموديول |
| `/detail` | تفاصيل بسطح وأقسام موحدة |
| `/form` | نموذج واحد للإنشاء/التعديل والتحقق والأخطاء وحماية المسودات |
| `/settings` | إعدادات فعلية تجريبية تحفظ داخل المعاينة |
| `/components` | إجراءات وحقول وشارات وتنبيهات، من الثيم المشترك |
| `/list?panel=edit&record=new` | لوحة مرتبطة بالمسار، تحت الهيدر وبجانب شريط الوحدات |

زر خيارات المعاينة يغيّر المظهر والحجم ولون المؤسسة وحالة البيانات. الألوان
الدلالية مستقلة عن لون المؤسسة، بما فيها التحذير المصحح للتباين. لوحة واحدة
للسجلات؛ تغيير التفاصيل إلى التعديل يستبدل محتواها. تأكيد المسودة هو الاستثناء
المركزي الوحيد المتداخل. روابط الصفحة الكاملة والرجوع والفلاتر قابلة للتجربة.

## المتبقي قبل التعميم

- مراجعة المستخدم للشكل المرجعي؛ تغيير المكونات يتم من مالكي الثيم والوصفات،
  لا بإضافة أشكال بديلة لكل صفحة.
- ترحيل صفحات العملاء وربطها ببياناتها وصلاحياتها على دفعات؛ لم يبدأ ذلك هنا.
- التنبيه المنخفض `GHSA-g7r4-m6w7-qqqr` في esbuild تحت fontless ما زال قائمًا
  في القفل، يخص خادم تطوير Windows. موديول الخطوط معطل، والتشغيل الحالي Mac
  وloopback فقط. لم نضع override عابرًا أو نخفي audit؛ يلزم حسمه قبل التبني العام.
- التحقق البصري لا يغطي كل نص طويل/حجم/مكوّن مستقبلي. الفحص الساكن لا يغني
  عن الاختبارات والمراجعة؛ لا هوك موافقة أو ادعاء حماية آلية مطلقة.

فحص السياسة مربوط ببداية `npm test` في root package.json، دون تغيير اعتماديات
الجذر أو ملف القفل. يشغّل الاختبارات المعتادة فقط بعد اجتيازه؛ ليس هوكًا
للأدوات ولا يعيد نظام الموافقات الذي ألغاه المستخدم.
