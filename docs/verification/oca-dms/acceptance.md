## النتيجة المنفذة

- تطبيق `webvue_documents` مستقل يستخدم OCA DMS المثبّت دون تعديل مصدره، وواجهة
  `/documents` للقراءة والإنشاء والتحرير وإدارة الوصول والملفات.
- `webvue_documents_hr` جسر اختياري للقسم وتقارير الانتهاء. أزيل نموذج HR القديم
  وواجهته البرمجية وقدراته؛ الروابط القديمة تحويل تنقل إلى المستند نفسه.
- المنح مصدر واحد: قدرة المستخدم مع نطاق السجل والشركة الحالية. الجديد مقيّد
  بمنحة محرر للمنشئ، والمهاجر يحتفظ برؤية الشركة. لا وصول ضمني لمسؤول النظام.
- خمس قدرات منفصلة للقراءة والإدارة والأرشفة والوصول والمكتبة. نقل قدرات HR
  القديمة يحافظ على هويات الأدوار والتعيينات دون منح صلاحيات الأرشفة أو الوصول.
- revision للحفظ والملفات والوصول، وتعارض HTTP409 يحفظ المسودة. إجراءات الملفات
  مستقلة عن إلغاء تحرير النص، وحد الملف 10MiB مع استخدام حصة المرفقات الأصلية مرة واحدة.
- التنزيل خاص، دون token يتجاوز السياسة أو تحويل خارجي، مع HEAD/Range
  و`private, no-store` و`nosniff`. تشمل الحماية ORM والتصدير والتجميع SQL وطرق OCA الأصلية.

## ما كشفته المراجعة والقبول وأُصلح

قراءة `ir.attachment.read` ثم التجميع SQL كانت تتجاوز أرشفة ملف DMS. أثبت الاختبار
السلبي تسرب النص المفهرس، ثم أضيفت قاعدة قراءة ORM ترتبط بالملف القانوني
والسجل والشركة، مع حراسة القراءة والنسخ والتصدير للكاش الدافئ. حراسة جهة استقبال
الملف والمجلد تمنع نقل مورد غير مُدار إلى المكتبة دون العملية المحمية؛ قيود الربط
تمنع ربط المرفق بسجل آخر أو إنشاء ملف قانوني ثانٍ له.

كشف HTTP الفعلي كاش قواعد قديمًا بعد إغلاق الميزة ثم فتح القراءة المحتفظ بها.
أضيف إبطال محلي وبعد commit عند تغير سياسة القراءة، مع نشره للعاملين عبر Odoo
حتى عند استعمال CLI لا ينفذ خاتمة HTTP. حصة التخزين لا تبطل الكاش مع كل رفع.
أداة القبول تتبع بروتوكول المشغل `commit` ثم `registry.signal_changes()`؛ واختبار
منفصل يتعمد حذف الخطوة الثانية أثبت نجاح الإضافة نفسها في نشر التغيير.

كشف بناء الإنتاج إدراج مساعد اختبارات الصفحات في حزم العميل. استُبعدت مجلدات
`__tests__` من Nuxt، ولم تُنسخ TypeScript/Vitest إلى الناتج. كشف المتصفح اختلاف
IDs بين عنوان الحقل وإدخاله بعد SSR؛ أضيفت IDs صريحة لعناصر نموذج المستند.
اختبارات الرحلات تتشارك كاش متصفح عميل طبيعي وصفحات منفصلة، مع إبقاء حدود Caddy
وقوائم السماح الأصلية دون تغيير.

## الفحص الأوسع وحدود النتيجة

الفحص الموسع لـOdoo نفّذ 978 اختبارًا وكشف فشلين و8 أخطاء تهيئة خارج المستندات:
ترتيب مرفقات PMO، وتاريخ استحقاق في المالية، وحقول account المفقودة في registry
جزئي أثناء اختبارات الاجتماعات at_install. لم يُعلن هذا التشغيل أخضر.

أُعيد اختبار المالية والاجتماعات على المصدر الأصلي نفسه، فتكررا دون إضافات
المستندات. ترتيب PMO يأتي من `list(set(...))` في Odoo؛ نجحت حالته على IDs أولية
ثم تكرر الفشل على المصدر الأصلي عند نقل IDs إلى حد تجزئة مختلف بتهيئة اختبارية
مؤقتة فقط. لم يُعدّل مصدر هذه التطبيقات أو تُضعف assertions لتجاوز الإخفاقات.
الأدلة: `/tmp/webvue-docs-crossapp.log`، `/tmp/webvue-docs-baseline-control3.log`،
`/tmp/webvue-docs-baseline-order-control.log`.

بناء `packages/contracts` لديه خطآن TS2531 سابقان في اختبار اجتماعات nullable
عند السطرين 22 و23. تكررا بفحص مصدر baseline الأصلي نفسه؛ لم يُعلن البناء الكلي
للمنتج أخضر. الأدلة `/tmp/webvue-docs-contracts-build-final.log` و
`/tmp/webvue-docs-contracts-build-baseline.log`. بناء Nuxt الإنتاجي وفحص أنواعه
واختبارات عقود الواجهة نجحت كما هو موضح أعلاه.

التحقق المحلي على Linux arm64 وحواف HTTP؛ لم يُختبر TLS أو مرشح amd64 هنا.
التحقق المحلي لا يساوي نشرًا. الترحيل الفعلي يحتاج inventory ونسخة database مع
filestore وصيانة مخططة؛ Odoo يعتمد commit لكل إضافة، لذلك لا يُفترض rollback
شامل للترقية. الاستئناف مدعوم، والرجوع يعيد النسخة المزدوجة والصورة السابقة.
سياسة تجارية موقّعة تحتاج انتقالًا معتمدًا عبر مسار المشغل بعد تسجيل التطبيق
وقبل فتح الخدمة؛ لا تعيد migration كتابة authority أو digest.
راجع [عقد الترحيل والاستعادة](migration-contract.md).

موارد Docker وبيانات القبول اصطناعية ومعزولة؛ ملفات الحالة وبيانات دخول الاختبار
خاصة محليًا. لم تُحذف volumes أو موارد مشاريع أخرى. WebSocket ليس جزءًا من
قبول المستندات في هذه البيئة الاختبارية. جلسات shared استعملت تسجيل Odoo حقيقيًا
ثم codec الحارس؛ لم يُختبر تسجيل دخول متصفح shared هنا. رحلات المتصفح كانت
عبر dedicated في الوضعين.

قياس الاستهلاك جزئي: التقط baseline المنسق متأخرًا، ولم تتوفر baselines مبكرة
للعامل والمراجع. الاستهلاك المنسوب الكامل غير معروف، ولا يوجد ادعاء توفير حصة.
