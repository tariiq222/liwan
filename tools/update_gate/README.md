# بوابة الموافقة على تحديثات نسق

**القاعدة:** فحص → تقرير عربي → موافقة طارق على التحديث المحدد → تطبيق
النطاق الموافق عليه → تحقق. تشمل التحديثات الأمنية وحدها. لا يمنح تركيب هذه
البوابة موافقة على أي تحديث. السياسة الملزمة: [UPDATE_POLICY](../../docs/UPDATE_POLICY.md).

## التقرير والموافقة

انسخ `report-template.json` إلى ملف تقرير مستقل واملأه بأدلة فعلية. القالب
غير صالح للموافقة كما هو. يشمل التقرير:

- `components`: كل مكوّن، الإصدار/الـcommit الحالي والمقترح، روابط المصادر
  الرسمية، الإصلاحات الأمنية، والتغييرات غير الأمنية. لا تكتفِ بعنوان الإصدار.
- `classification`: `security_only` أو `mixed` أو `core` أو `unknown`.
- `impact`: أثر التحديث على الكور والاجتماعات والمشاريع وHR والصلاحيات
  والمحادثات والواجهة والتخصيصات؛ اشرح سبب عدم التأثر إذا كان كذلك.
- `verification_plan`: خطة التوافق والأمان واختبارات الانحدار دون تشغيل تحديث.
- `rollback_plan`: النسخة الاحتياطية ونطاق البيانات وخطوات الرجوع.
- `actions`: إجراءات التغيير المحمية فقط وبترتيب التنفيذ؛ الفحوصات للقراءة
  توضع في `verification_plan`. لكل إجراء `cwd` مطلق و`tool_name` و`tool_input`.

الإجراءات تستخدم الصيغة **بعد التطبيع**: أمر الطرفية اسمه `Bash` ومعاملاته
`{"command":"الأمر بالحروف نفسها"}` فقط، دون timeout أو وصف الأداة.
التعديل يستخدم `Edit`/`Write` ومعامل `file_path`، والـpatch يستخدم
`apply_patch` ومعامل `command` للنص الكامل. لا تجمع التحديث مع أوامر غير
مراجعة، ولا تستخدم `latest` أو فروعًا متحركة بدل تثبيت النسخة المقصودة.

يتحقق الوكيل من اكتمال التقرير للقراءة فقط:

```sh
python3 /Users/tariq/code/nasq/tools/update_gate/gate.py validate /absolute/path/report.json
```

بعد قراءة التقرير والاتفاق على التحديث، ينفذ **طارق بنفسه في طرفية مستقلة**:

```sh
python3 /Users/tariq/code/nasq/tools/update_gate/gate.py approve /absolute/path/report.json
```

يعرض الأمر التقرير وبصمته ويطلب تأكيدًا صريحًا مربوطًا بتلك البصمة. يُمنع
على الوكيل تشغيل الموافقة بطرفية تفاعلية أو إدخال التأكيد نيابة عن المستخدم.
الرفض أو إغلاق الطرفية لا يصدر إذنًا. الموافقة صالحة ساعة واحدة وتُستهلك حسب
ترتيب الإجراءات مرة واحدة لكل إجراء. تغيير التقرير أو الأمر أو المجلد أو
انتهاء المدة يوقف التنفيذ. لا تمنح الموافقة على تقرير آخر إذنًا عامًا.

ملف الموافقة المحلي هو `.runtime/update-approval/approved.json`، ولا يدخل Git.
لا توجد موافقة جاهزة في المستودع. لأن الهوك يستهلك الإجراء قبل التنفيذ، فإن
رفض أداة أخرى له أو فشله لا يعيد الإذن؛ يلزم تقرير/موافقة جديدة للمحاولة.
لا تفترض أن حالة النظام لم تتغير: أعد مطابقة الإصدار الحالي قبل طلب الموافقة.

## الربط والتفعيل

`install.py` يربط أدوات المشروع بالنسخة المشتركة في المسار الأساسي، ويحافظ
على الإعدادات والهوكات السابقة. لا يعدل اعتمادًا أو خدمة أو قاعدة بيانات.
يفحص جميع الملفات قبل الكتابة، ويحفظ نسخًا من الملفات المتغيرة في
`.runtime/update-gate-install/<timestamp>/manifest.json`.

```sh
# معاينة ملفات التركيب، ثم تركيب البوابة المصرح بها فقط:
python3 tools/update_gate/install.py --all-worktrees
python3 tools/update_gate/install.py --all-worktrees --apply
```

أعد تشغيل المثبّت عند إنشاء worktree قديم/جديد لا يحمل إعدادات الأدوات.
أعد فتح جلسات الوكلاء بعد التركيب؛ لا تفترض إعادة التحميل في جلسة قائمة.

| الأداة | الربط | حدود التفعيل |
| --- | --- | --- |
| Codex | `.codex/hooks.json` في النسخة الأساسية ونسخ العمل الحالية، يشير إلى محوّل واحد | يجب اعتماد workspace وتعريف الهوك من `/hooks`؛ لا نفترض أن الفروع ورثت الثقة أو الإعدادات قبل اكتشافها فعليًا |
| Claude | إضافة `PreToolUse` إلى `.claude/settings.json` | الهوك القديم محفوظ؛ يلزم تحميل إعدادات الجلسة |
| OpenCode | `.opencode/plugins/nasq-update-gate.js` | إضافة بلا حزم جديدة؛ ترمي خطأ قبل التنفيذ عند المنع |
| Grok | `.grok/hooks/nasq-update-gate.json` | يحتاج ثقة المشروع؛ المحوّل يمنع ازدواج هوك Claude/Cursor المتوافق |
| VS Code Copilot | `.github/hooks/nasq-update-gate.json` | يتطلب جلسة Agent تدعم Hooks وثقة workspace |
| Gemini | `.gemini/settings.json` | إعداد مُجهّز وفق الوثائق؛ البرنامج غير متحقق محليًا |
| Cursor | `.cursor/hooks.json` وقاعدة alwaysApply | إعداد مُجهّز وفق الوثائق؛ البرنامج غير متحقق محليًا |
| أي وكيل/أداة أخرى | `AGENTS.md` و`CLAUDE.md` و`GEMINI.md` و`GROK.md` وتعليمات Copilot | سياسة تعليمات فقط إلى أن يُثبت ربط هوك الأداة |

## حدود الحماية الفعلية

هذه بوابة لتقليل التحديثات غير المقصودة، وليست عزلًا أمنيًا عن عملية تملك
صلاحيات المستخدم نفسه. تكتشف أوامر التحديث المعتادة وكتابة manifests/locks
وملفات الموردين والحماية، لكنها لا تثبت سلامة برنامج عشوائي أو مشفّر أو MCP
خارجي. تمرير أوامر لاحقة إلى shell قائم، ومنها `write_stdin` في Codex، لا
يستدعي دائمًا هوكًا جديدًا. يمنع الوكيل استخدام هذه المسارات لتجاوز البوابة.

التحقق الآلي من التقرير يثبت بنية البيانات وربط الموافقة؛ لا يثبت صحة كلام
الوكيل أو أن الرابط رسمي بالفعل أو خلو الإصدار من ثغرات. يجب مراجعة المصادر
والـdiff وأثرها قبل عرضه للمستخدم. فشل/انتهاء مهلة تشغيل الهوك لدى بعض
الأدوات قد يسمح بالفعل حسب سلوك الأداة؛ لا تعتبر الجلسة محمية دون التحقق من
تحميله وثقته. الإعدادات مثبتة محليًا، وليست حماية تلقائية لخوادم بعيدة أو
أجهزة أخرى. لا تُعطَّل حماية مصدر Odoo أو منع اختبارات `odoo19` بهذه البوابة.

المراجع: [Codex hooks](https://developers.openai.com/codex/hooks)،
[Claude hooks](https://code.claude.com/docs/en/hooks)،
[OpenCode plugins](https://opencode.ai/docs/plugins/)،
[VS Code hooks](https://code.visualstudio.com/docs/agent-customization/hooks)،
[Gemini hooks](https://geminicli.com/docs/hooks/reference/)،
[Cursor hooks](https://cursor.com/docs/hooks). توثيق Grok المحلي:
`/Users/tariq/.grok/docs/user-guide/10-hooks.md`.
